# Toplink Source Grounding

## Read in this order

1. `spec.md` and `RULES.md`.
2. `docs/system/toplink-knowledge-brief.md`.
3. The relevant canonical owner: `docs Toplink/TOPLINK_PAGE_MASTER_PLAN.md` for strategy or `TOPLINK_PAGE_MILESTONES.md` for execution.
4. Only the specific evidence file named by the request: positioning, safety, product, formula, script, or brand profile.

## Build a source ledger

For every material statement, record: statement, source path/location, status, allowed use, and missing proof.

- Use `TOPLINK_CONFIRMED` only for the source's exact meaning.
- Use `INFERENCE` for a reasoned conclusion and include a validation path.
- Use `HYPOTHESIS` for audience, positioning, performance, or pillar proposals not yet measured.
- Use `MISSING_INPUT`, `UNVERIFIED`, or `DO_NOT_USE` for facts that cannot support public language.

Do not turn a source sentence into a stronger medical, legal, product, availability, price, qualification, franchise, founder, or performance claim.

## Output

Return a compact table with `usable now`, `conditional`, `blocked`, and `questions for the human owner`. Cite paths rather than copying long source passages. If the source is insufficient, stop at the ledger; do not invent a bridge.

## Required checks

- Separate Toplink evidence from any Thảo Tây context.
- Treat Page identity, offer readiness, legal/public franchise wording, product dossiers, and Sheet targets as blocked unless directly verified.
- Route health-sensitive language to `$toplink-communication-safety` before public use.
